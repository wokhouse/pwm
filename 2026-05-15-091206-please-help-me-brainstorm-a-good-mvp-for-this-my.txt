⏺ Empty repo with just a README. Good starting point. Here's my analysis of your
   MVP idea:

  "Petite Worktree Manager" — MVP Brainstorm

  Core Problem You're Solving

  Running multiple coding agents (Claude Code, etc.) in parallel across git
  worktrees is tedious. The workflow is: create a branch, create a worktree, cd
  into it, launch an agent, monitor it, repeat. You want one tool that
  orchestrates all of this.

  Recommended MVP Scope

  I'd suggest stripping it down further than your 3 candidates for v1. Here's my
   reasoning:

  Tier 1 — Ship First (True MVP)
  1. pwm init — Scaffold .pwm/ in a repo, record config (default branch, agent
  command template)
  2. pwm create <name> — Create a git worktree inside .pwm/<name>/, linked to a
  new branch <name>
  3. pwm spawn <name> [--agent <cmd>] — Launch an agent process inside a
  worktree, track its PID and status
  4. pwm ls — Table view of all worktrees + branch + agent status
  (running/done/crashed/needs-input)
  5. pwm attach <name> — Jump into the worktree's agent tmux/screen session
  6. pwm rm <name> — Kill agent, remove worktree, delete branch

  Tier 2 — Polish (v1.1)
  7. TUI sidebar navigator (your #1) — an interactive pwm (no args) that opens a
   terminal UI showing worktrees as a list you can navigate
  8. Terminal multiplexing (your #2) — built-in tab management, probably via
  tmux session management under the hood

  Tier 3 — Future
  9. Agent output streaming / log tailing
  10. Configurable agent templates (Claude Code, Aider, Cursor, etc.)
  11. Merge/PR workflow integration
  12. Resource monitoring (CPU/memory per agent)

  Why This Ordering?

  - Agent status at a glance is the highest-value feature and is achievable in a
   simple ls command — no TUI needed for v1
  - TUI/sidebar is the biggest engineering investment with the most dependency
  complexity (Ink, terminal rendering, keyboard handling) — validate the core
  workflow first with pure CLI commands
  - Terminal tabs implies you need to choose a multiplexing strategy (tmux?
  zellij? custom?) — this is an architectural decision that benefits from
  real-world usage first

  Key Architectural Decisions to Make Early

  Decision: Process management
  Options: Raw child processes vs. tmux sessions vs. systemd-user units
  ────────────────────────────────────────
  Decision: State storage
  Options: .pwm/state.json vs. sqlite vs. filesystem-only
  ────────────────────────────────────────
  Decision: Agent detection
  Options: Parse exit codes + stdout heuristics vs. require agents to write
    status files
  ────────────────────────────────────────
  Decision: Distribution
  Options: npm global install vs. npx vs. homebrew

  My Recommendation for Process Management

  Use tmux sessions under the hood. Each pwm spawn creates a tmux session named
  pwm-<name>. This gives you:
  - Detachable processes for free
  - pwm attach is just tmux attach -t pwm-<name>
  - Agent output is captured in tmux's scrollback
  - Status checking via tmux list-sessions + process existence

  Concrete MVP Session Flow

  $ cd my-project
  $ pwm init                          # creates .pwm/, stores config

  $ pwm create feature-auth           # worktree at .pwm/feature-auth
  $ pwm create feature-api            # worktree at .pwm/feature-api

  $ pwm spawn feature-auth            # launches claude-code in
  .pwm/feature-auth
  $ pwm spawn feature-api             # launches claude-code in .pwm/feature-api

  $ pwm ls                            # shows:
    # NAME           BRANCH              AGENT     STATUS
    # feature-auth   feature-auth        claude    running (12m)
    # feature-api    feature-api         claude    needs-input ⚠

  $ pwm attach feature-api            # jumps into that agent's session
  # (agent asks a question, user answers, detaches)

  $ pwm rm feature-auth               # kills agent, removes worktree + branch

  Tech Stack for TypeScript CLI

  - Runtime: Node.js (not Bun/Deno — widest compatibility)
  - CLI framework: commander or yargs
  - TUI (Tier 2): ink (React for terminal) or blessed
  - Git operations: shell out to git directly (don't use a git library —
  worktree commands change fast)
  - Process management: child_process + tmux
  - State: .pwm/state.json — keep it dead simple

  Key Design Decisions for Remote-First

  State file: .pwm/state.json tracks worktrees, branches, agent PIDs, spawn
  timestamps. This is your source of truth — tmux is just the presentation
  layer.

  tmux session naming: pwm-<repo-hash> — allows multiple projects on one server
  without collision.

  Agent status detection: Rather than trying to parse agent output (fragile),
  use a convention:
  - Agent is "running" if its PID is alive
  - Agent is "needs-input" if the tmux pane's process has been waiting > N
  seconds on stdin (detectable via /proc or ps stat)
  - Agent is "done" if PID exited with code 0
  - Agent is "failed" if PID exited with code != 0

  Sidebar refresh: A background process that re-renders the sidebar pane every
  few seconds by reading state.json + checking process status.

  The SSH Workflow

  # On your server
  $ cd ~/projects/my-app
  $ pwm init
  $ pwm create feature-auth
  $ pwm create feature-api
  $ pwm spawn feature-auth        # starts agent, runs in tmux
  $ pwm spawn feature-api         # starts agent, runs in tmux
  $ pwm up                        # enter the session
  # ... check on agents, interact with one that needs input ...
  # Ctrl+b d (standard tmux detach) — or `q` from sidebar

  # Close laptop. Go outside. Come back.

  $ ssh my-server
  $ pwm up                        # reattach, everything still running

⏺ Good findings. Here's what changes when you lock into Claude Code:

  Claude Code-Native Integration

  The Big Win: --output-format stream-json

  Instead of guessing agent state from PIDs, you can parse Claude Code's
  real-time event stream. Each worktree's agent emits structured JSON lines you
  can tail and aggregate into the sidebar.

  This turns the sidebar from:

  ● feature-auth   running (12m)     # all we know generically

  into:

  ● feature-auth
    branch: feat/auth
    status: editing
    file: src/auth/login.ts
    tool: Edit (3rd call)
    tokens: 45k / 200k
    last action: wrote src/auth/middleware.ts

  What This Unlocks for the MVP

  1. Rich status detection — no heuristics needed

  Tail the stream-json output. Key events you can react to:

  ┌───────────────────────────────┬─────────────────────┐
  │             Event             │    Sidebar shows    │
  ├───────────────────────────────┼─────────────────────┤
  │ tool_call with tool Bash      │ running: npm test   │
  ├───────────────────────────────┼─────────────────────┤
  │ tool_call with tool Edit      │ editing: src/foo.ts │
  ├───────────────────────────────┼─────────────────────┤
  │ tool_call with tool Read      │ reading: src/bar.ts │
  ├───────────────────────────────┼─────────────────────┤
  │ content_delta                 │ thinking...         │
  ├───────────────────────────────┼─────────────────────┤
  │ Waiting for permission prompt │ ⚠ needs approval    │
  ├───────────────────────────────┼─────────────────────┤
  │ Process exits code 0          │ ✓ done              │
  ├───────────────────────────────┼─────────────────────┤
  │ Process exits code 1          │ ✗ failed            │
  └───────────────────────────────┴─────────────────────┘

  2. Session resumption with --continue

  Claude Code stores sessions as .jsonl files under ~/.claude/projects/. You can
   store the session ID per worktree in state.json and offer:

  pwm resume feature-auth   # claude --continue <session-id> inside that 
  worktree

  This means if an agent crashes or the server restarts, you don't lose the
  conversation context.

  3. Print mode (-p) for non-interactive spawning

  Use claude -p --output-format stream-json inside each tmux pane. This strips
  the TUI and gives you clean NDJSON output while still being fully functional.
  You can:

  - Tail the output file for the sidebar
  - Keep the tmux pane available for manual pwm attach if needed
  - Or run it purely headless and only show the sidebar

  4. Cost and token tracking

  The stream output includes token counts. You can aggregate across all
  worktrees and show total spend in the sidebar footer.

  How It Works Under the Hood

  .pwm/
    state.json              # worktree metadata, session IDs, PIDs
    feature-auth/
      (git worktree files)
      .claude-output.jsonl   # tee'd stream-json output from claude
    feature-api/
      (git worktree files)
      .claude-output.jsonl

  pwm spawn feature-auth does:

  1. Create a new tmux window
  2. Run: cd .pwm/feature-auth && claude -p --output-format stream-json 2>&1 | 
  tee .claude-output.jsonl
  3. Store PID + session ID in state.json
  4. Sidebar background process tails all .claude-output.jsonl files and renders
   status

  Sidebar refresh loop (runs in the sidebar tmux pane):

  1. Read state.json for worktree list
  2. For each worktree, tail the last ~20 lines of .claude-output.jsonl
  3. Parse the latest tool_call, token count, etc.
  4. Check if PID is still alive
  5. Re-render sidebar

  Key Tradeoff: -p (non-interactive) vs Interactive

  You have two modes to offer:

  - pwm spawn <name> "implement auth" — runs claude -p "implement auth"
  non-interactively, agent goes until done or blocked
  - pwm spawn <name> -i — runs interactive claude (no -p), user can attach to
  collaborate

  Both emit stream-json (or can be tee'd). I'd support both in the MVP.

  What This Locks You Out Of

  The honest tradeoff: you're coupled to Claude Code's output format. If it
  changes, your parser breaks. Mitigation:

  - Keep the parser in one file (src/claude/parser.ts) so it's easy to update
  - The stream-json format is likely stable since it's a documented public
  interface
  - Even if parsing fails, you fall back to PID-alive/dead detection

     │ #!/usr/bin/env node                                                     │
     │ - .gitignore (node_modules, dist, .pwm)                                 │
     │ - npm link for local development                                        │
     │                                                                         │
     │ Step 2: pwm init                                                        │
     │                                                                         │
     │ - Detect we're inside a git repo (check for .git/ or git rev-parse)     │
     │ - Create .pwm/ directory                                                │
     │ - Write .pwm/config.json with defaults                                  │
     │ - Write .pwm/state.json with empty worktrees map                        │
     │ - Add .pwm/ to repo's .gitignore if not already present                 │
     │                                                                         │
     │ Config schema:                                                          │
     │ {                                                                       │
     │   "project": "<repo dirname>",                                          │
     │   "defaultAgent": "claude",                                             │
     │   "agentCommand": "claude -p --output-format stream-json"               │
     │ }                                                                       │
     │                                                                         │
     │ State schema:                                                           │
     │ {                                                                       │
     │   "worktrees": {}                                                       │
     │ }                                                                       │
     │                                                                         │
     │ Step 3: pwm create <name>                                               │
     │                                                                         │
     │ - Validate .pwm/ exists (must run init first)                           │
     │ - Validate name is a valid git branch name, not already taken           │
     │ - Run git worktree add .pwm/<name> -b <name> (creates branch +          │
     │ checkout)                                                               │
     │ - Add entry to state.json:                                              │
     │ {                                                                       │
     │   "worktrees": {                                                        │
     │     "<name>": {                                                         │
     │       "branch": "<name>",                                               │
     │       "path": ".pwm/<name>",                                            │
     │       "agent": null                                                     │
     │     }                                                                   │
     │   }                                                                     │
     │ }                                                                       │
     │                                                                         │
     │ Step 4: pwm spawn <name> [prompt]                                       │
     │                                                                         │
     │ - Validate worktree exists in state                                     │
     │ - Validate tmux is installed                                            │
     │ - Check if a pwm tmux session exists, create if not:                    │
     │   - Session name: pwm-<repo-hash> (first 8 chars of hashed absolute     │
     │ path)                                                                   │
     │   - Created detached (-d)                                               │
     │ - Create a new tmux window in that session, named <name>                │
     │ - Build the claude command:                                             │
     │   - Non-interactive: cd <abs-path-to-worktree> && claude -p "<prompt>"  │
     │ --output-format stream-json 2>&1 | tee                                  │
     │ <abs-path-to-worktree>/.claude-output.jsonl                             │
     │   - If no prompt: cd <abs-path-to-worktree> && claude --output-format   │
     │ stream-json 2>&1 | tee <abs-path-to-worktree>/.claude-output.jsonl      │
     │ - Send the command to the tmux window via send-keys                     │
     │ - Record agent info in state:                                           │
     │ {                                                                       │
     │   "agent": {                                                            │
     │     "pid": null,                                                        │
     │     "claudeSessionId": null,                                            │
     │     "mode": "print",                                                    │
     │     "spawnedAt": "<ISO timestamp>",                                     │
     │     "status": "running"                                                 │
     │   }                                                                     │
     │ }                                                                       │
     │ - Note: PID tracking requires echo $! after the command; this is a      │
     │ refinement for later                                                    │
     │                                                                         │
     │ Step 5: pwm ls                                                          │
     │                                                                         │
     │ - Read state.json                                                       │
     │ - For each worktree:                                                    │
     │   - Check if .claude-output.jsonl exists and tail last 100 lines        │
     │   - Parse latest events for: current tool call, token usage, status     │
     │   - Check if the tmux window for that worktree still has a running      │
     │ process                                                                 │
     │ - Render a table using console.table or manual formatting:              │
     │ NAME            BRANCH          STATUS        LAST ACTION               │
     │ TOKENS    COST                                                          │
     │ feature-auth    feature-auth    running       editing: auth.ts    45k   │
     │      $1.83                                                              │
     │ feature-api     feature-api    needs-input   awaiting approval   38k    │
     │     $1.24                                                               │
     │ fix-typos       fix-typos      idle          —                   0      │
     │     $0.00                                                               │
     │                                                                         │
     │ Step 6: Stream-json parser (src/agent/parser.ts)                        │
     │                                                                         │
     │ Parse individual NDJSON lines from Claude Code's stream-json output.    │
     │ Key events to extract:                                                  │
     │                                                                         │
     │ ┌───────────────────────────────────────────────┬────────────────────── │
     │ ┐                                                                       │
     │ │                 Event pattern                 │       Meaning         │
     │ │                                                                       │
     │ ├───────────────────────────────────────────────┼────────────────────── │
     │ ┤                                                                       │
     │ │ type: "assistant", content has tool_use block │ Agent calling a tool  │
     │ │                                                                       │
     │ ├───────────────────────────────────────────────┼────────────────────── │
     │ ┤                                                                       │
     │ │ tool_use with name Edit, input has file_path  │ Editing a file        │
     │ │                                                                       │
     │ ├───────────────────────────────────────────────┼────────────────────── │
     │ ┤                                                                       │
     │ │ tool_use with name Bash, input has command    │ Running a command     │
     │ │                                                                       │
     │ ├───────────────────────────────────────────────┼────────────────────── │
     │ ┤                                                                       │
     │ │ tool_use with name Read, input has file_path  │ Reading a file        │
     │ │                                                                       │
     │ ├───────────────────────────────────────────────┼────────────────────── │
     │ ┤                                                                       │
     │ │ type: "assistant", usage field present        │ Token usage update    │
     │ │                                                                       │
     │ ├───────────────────────────────────────────────┼────────────────────── │
     │ ┤                                                                       │
     │ │ File ends without exit                        │ Still running         │
     │ │                                                                       │
     │ └───────────────────────────────────────────────┴────────────────────── │
     │ ┘                                                                       │
     │                                                                         │
     │ - Last non-empty line with a type field = latest event                  │
     │ - Count lines to estimate activity                                      │
     │ - Look for usage fields to accumulate token counts                      │
     │                                                                         │
     │ Step 7: tmux helper module (src/tmux/index.ts)                          │
     │                                                                         │
     │ Thin wrappers around tmux CLI:                                          │
